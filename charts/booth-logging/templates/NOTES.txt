WHO CAN READ WHICH LOGS (ADR 0067 as amended by ADR 0077; operators per ADR 0094)
  Platform operators (tokens whose groups claim holds "/platform/operator", granted in the
  identity provider) read ALL logs, platform-wide. If nobody holds it, nobody can read shared
  platform logs (core, storage, catalog, ...).
  Other workspace owners read only their own workspace's pods: those labelled
  booth.projectbooth.io/workspace=<workspace> (e.g. notebook servers). Editors and viewers
  read nothing.

!! THE GRAFANA VIEW RUNS ARBITRARY LogQL OVER EVERY TENANT'S LOGS. It admits PLATFORM OPERATORS
!! ONLY; everyone else is refused outright. To remove it: --set grafana.enabled=false

!! Grafana sees only booth-core's X-Booth-Identity assertion, never the caller's own token. Until
!! booth-core carries /platform/operator into that assertion (ADR 0094's amendment), NOBODY is
!! admitted. That is expected, not broken.

Grafana verifies booth-core's signed X-Booth-Identity assertion against core's keys, fetched
at pod start from:
  {{ .Values.grafana.identity.issuerUrl }}
This must equal booth-core's iframe-identity issuer EXACTLY (".svc.cluster.local:8080", not
".svc:8080"). If it doesn't, the Grafana pod's fetch-jwks init container fails and says why:
  kubectl -n {{ .Release.Namespace }} logs deploy/{{ include "booth-logging.grafanaName" . }} -c fetch-jwks
If booth-core's iframe-identity key is ever regenerated (its booth-iframe-identity-keys Secret
deleted), Grafana refuses everyone until restarted:
  kubectl -n {{ .Release.Namespace }} rollout restart deploy/{{ include "booth-logging.grafanaName" . }}
